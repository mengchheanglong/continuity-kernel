## GREEN implementation

`migrations/001_continuity.sql` creates:

- `continuity.authorization_grants`;
- `continuity.cases`;
- `continuity.command_receipts`;
- `continuity.accepted_history`;
- `continuity.decision_audit`;
- `continuity.commit_command(text,text,jsonb,integer,integer)`.

The function:

- is owned by non-login `continuity_owner`;
- is `SECURITY DEFINER` with `search_path=pg_catalog`;
- uses only schema-qualified domain objects and no dynamic SQL;
- serializes namespace/command receipts with a transaction advisory lock;
- compares durable request hashes before mutation;
- locks authorization grant before case state;
- rejects unsupported request, validator, projection, authorization, and expected-case versions;
- atomically writes case state, accepted history, and receipt;
- returns the stored outcome for same-ID/same-hash replay;
- rejects same-ID/different-hash reuse without replacing the original receipt;
- stores semantic `world_time` separately from wall-clock `ingestion_time`;
- stores only opaque `PayloadRef`, never optional payload bytes or plaintext-derived payload hashes.

The TypeScript test adapter computes projection digest from the returned projection using the already verified RFC 8785/SHA-256 canonicalizer. The digest is not hardcoded in SQL.

- concurrent same-ID/same-hash replay with one receipt/history transition;

- distinct-command expected-version race with one accepted and one conflict;
- revocation-first rejection;
- command-first acceptance while revocation waits on the grant lock;
- enclosing transaction rollback leaves no state, receipt, or history;
- exact projection digest `AEMpcJ6pJpNog4XeTOqNybf6SvWYmyCJVoPeOikywUs`;
- unsupported request-hash, validator, and projection versions fail closed.
